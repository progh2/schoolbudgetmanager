# 예산지기 진행 방식

저장소: (예정) https://github.com/progh2/schoolbudgetmanager

## 마일스톤
- M1 기본 장부: 사업·배정·항목·집행·현황표·백업
- M2 에듀파인 업로드: 읽기·매핑·미리보기·중복·수동 매칭
- M3 증빙: 첨부·필수 판정·검토·규정 검색
- M4 점검·대시보드: 마감·한도 경고, 대시보드, 자동 백업
- M5 계획 변경·추경: 변경안 상태기계, 전후 비교, 시점 조회
- M6 데스크톱(옵션) · M7 Firebase(옵션)

## 규칙
1. 새 일은 이슈로 만든다. 이슈 없이 코드부터 쓰지 않는다.
2. 구현은 해당 이슈의 완료 기준만 맞춘다.
3. 머지할 때마다 아래 「진행」에 왜 그렇게 했는지 한 단락.

## 진행
- 2026-11-07 M0: BizCoder(소넷)가 만든 초안 v0.1(PRD·ARCHITECTURE·DATA_MODEL·ROADMAP·BACKLOG·GIT_WORKFLOW 6종)을 PRD v0.2·ARCHITECTURE·issues/로 다시 썼다. 문서를 6종에서 3종 + 이슈로 줄였다(데이터 모델은 구조 문서 안으로, 로드맵·백로그는 이슈 파일과 STATUS로). 바꾼 이유:
  - **빌드 없는 CDN 구조를 버렸다.** 테스트·타입 검사 없이 단계를 쌓으면 M3쯤 앞 단계가 몰래 깨진다. Vite + TS + Vitest로 `npm test`·`npm run build`를 머지 게이트로 둔다.
  - **`base: './'` + 해시 라우팅.** v0.1은 "상대 경로를 쓰자"는 다짐만 있었다. 다짐은 깨진다. 설정 한 줄로 고정하면 같은 `dist/`가 Pages 하위 경로와 Pod 루트 둘 다에서 돈다(techerplz처럼 `BASE_PATH`를 넣는 방식도 되지만, 배포처가 둘이면 상대 경로가 더 단순하다).
  - **역할 전환 삭제.** 단일 브라우저에서 통제 없는 역할 전환은 아무것도 막지 않는다. 승인은 기록으로만 남기고, 진짜 역할은 M7 보안 규칙에서.
  - **사업 상태(계획·운영·마감) 추가.** 운영 중 배정을 직접 고칠 수 있으면 추경 이력이 의미가 없다. 운영 중에는 변경안으로만 바뀐다. 마감은 "다시 열기"로 빠져나올 수 있어 막다른 상태가 아니다.
  - **업로드는 한도 초과도 반영.** 에듀파인이 기준 장부다. 현실을 거부하면 장부가 어긋난다. 수동 입력만 사유를 받는다.
  - **중복 키에 파일 안 순번.** 같은 날·같은 금액·같은 적요가 진짜 두 건일 수 있다. v0.1의 조합 키는 그중 하나를 지운다.
  - **백업은 zip.** JSON에는 증빙 파일이 안 들어간다.
  - **origin 주의.** `progh2.github.io`는 모든 Pages 프로젝트가 공유하고, Pages와 Pod는 서로 다른 저장소다. v0.1에 없던 내용.
  - **성공 지표 표 삭제.** 베이스라인이 없는 "누락률 5% 이하" 같은 수치는 확인할 방법이 없다. 마일스톤마다 테스트로 확인되는 완료 기준으로 바꿨다.
- 2026-11-07 M1 (#01~#07) 기본 장부. 원격 저장소가 아직 없어 이슈 일곱 개를 한 브랜치에서 만들고 로컬에서 스쿼시 머지했다. 원격이 생기면 이슈 단위 PR로 돌아간다.
  - **Repository를 CRUD에서 `transact` 하나로 좁혔다.** 계획에는 `put`·`softDelete`가 있었지만, 그러면 화면이 검증을 건너뛰고 쓸 수 있다. 도메인 명령을 순수 함수(`데이터, 입력, ctx → 쓰기 목록`)로 만들고 스토어의 `run()`만 `transact`를 부른다. `imports.test.ts`가 다른 호출자를 막는다. 덕분에 명령 테스트에 저장소가 필요 없다.
  - **전부 메모리에 올려 계산한다.** 1년치 1만 행이면 수 MB다. 잔액을 저장하지 않는다는 원칙을 지키면서도 화면이 즉시 반응한다.
  - **파일은 Blob이 아니라 ArrayBuffer로 저장한다.** 테스트(fake-indexeddb)와 브라우저에서 똑같이 복제되고, 백업 zip에 그대로 들어간다.
  - **SheetJS는 눌렀을 때 불러온다.** 한 덩어리로 묶으면 822 kB라 빌드 경고가 났다. 지연 로딩으로 첫 화면 493 kB, 경고 0.
  - **스모크(`npm run smoke`)**: Playwright로 `dist/`를 `/schoolbudgetmanager/` 하위 경로와 루트에 띄워 처음 시작 → 사업 → 배정(총액 초과 거부) → 항목 → 운영 시작 → 한도 초과 집행(사유) → 대시보드 52.0% → 새로고침 유지 → 엑셀·백업 내려받기까지 누른다. CI에서도 돈다. 스크린샷을 보고 성공 뒤에도 남던 오류 띠와 "한 번도 백업 안 함"을 "일주일 넘게"로 말하던 문구를 고쳤다.
  - 엑셀 머리글 고정(freeze)은 SheetJS 무료판이 쓰지 못해 뺐다. 열 너비·숫자 서식·요약 시트는 있다.
- 2026-11-07 M2 (#08~#11) 에듀파인 업로드.
  - **모든 셀을 문자열로 읽고 직접 바꾼다.** 엑셀 숫자 셀은 서식 문자열("1,234") 대신 원래 값을, 날짜 서식 숫자는 ISO로 바꾼다. 금액은 `(1,000)`·`△1,000`을 음수로, 소수가 남으면 거부. 날짜는 연도 없으면 거부.
  - **머리글 찾기는 "서로 다른 글자가 몇 개인가"로.** 병합된 제목 행은 모든 칸이 같은 값으로 채워져 칸 수로 세면 머리글처럼 보인다.
  - **CSV는 UTF-8을 엄격하게 먼저, 안 되면 CP949.** 둘 다 실패하면 멈추고 알린다(깨진 글자를 넣지 않는다). 픽스처 `tests/fixtures/edufine-cp949.csv`는 가상 자료다.
  - **중복 키에 파일 안 순번.** 고유번호 열이 있으면 그것만, 없으면 `날짜|금액|적요|과목|항목#n`. 같은 파일의 똑같은 두 건이 둘 다 들어가고, 같은 파일을 다시 올리면 전부 '이미 있음'이 된다(테스트·스모크 둘 다 확인).
  - **매칭 순서는 사용자 규칙 → 코드 → 이름.** 사람이 정한 것이 추측을 이긴다. 같은 코드 항목이 여럿이면 사업명으로 좁히고, 그래도 여럿이면 짐작하지 않고 '짝 없음'으로 둔다.
  - **짝 없는 행은 미분류로 반영할 수 있다.** 버리면 장부가 에듀파인과 어긋난다. 미분류는 잔액에서 빠지고 집행 화면에 경고로 남는다.
  - **반영 직전에 중복을 다시 본다.** 미리보기와 반영 사이에 다른 업로드가 끼면 거부하고 다시 미리보기를 요구한다.
  - 라이브러리를 react·vendor 묶음으로 나눠 첫 화면 경고를 없앴다(앱 90 kB + vendor 200 kB + react 219 kB).
- 2026-11-07 M3 (#12~#14) 증빙.
  - **판정은 필수 유형별 실제 파일로.** 같은 유형 두 장은 하나로 세고, 보완 필요로 반려된 파일은 갖춘 것으로 치지 않는다. 같은 유형의 새 파일을 붙이면 보완된 것으로 본다 — 보완 필요가 막다른 상태가 되지 않게.
  - **증빙은 지운 표시만 하고 파일은 남긴다.** 되돌릴 수 있게. 실제 파일 삭제는 하지 않는다(PRD 열린 질문: 보존 5년).
  - **증빙 준비 목록과 대시보드는 같은 함수(`evidenceChecklist`)를 쓴다.** 숫자가 화면마다 달라지지 않게.
  - **규정 검색은 PDF(pdf.js)·HWPX(zip 안 XML)만.** 구형 HWP·스캔 PDF는 이유를 말하고 "원문 열기"로 대신한다. 검색은 글자 사이 공백을 무시한다("강사수당"으로 "강사 수당"도 찾는다).
  - **pdf.js 워커를 `.js`로 묶는다.** 스모크가 잡았다: 기본 `.mjs` 워커는 `.mjs`를 JavaScript로 보내지 않는 서버에서 조용히 죽는다. Pod가 어떻게 보낼지 모르니 `new Worker(new URL(...))` 꼴로 바꿔 Vite가 `.js`로 내게 했다. 스모크 서버는 일부러 `.mjs`를 모르는 채로 둔다.
  - 스모크가 하나 더 잡았다: 파일 선택칸을 비우면 FileList도 비어 "0개를 붙였어요"가 떴다. 먼저 배열로 복사한다.
- 2026-11-07 M4 (#15~#17) 점검·대시보드·자동 백업.
  - **경고는 근거와 함께.** "교재 D-7"만으로는 왜인지 모른다. 규칙·기한·기준일·한도·집행을 한 줄로 붙인다. 경계값(D-14·D-7·D-1·D-day·지남, 90%·100%·초과)을 테스트로 고정했다.
  - **잔액이 없는 항목은 마감 경고를 하지 않는다.** 쓸 돈이 없으면 기한은 문제가 아니다. 마감한 사업도 뺀다.
  - **대시보드 위젯 정의를 코드 맨 위 주석에 적었다**(무엇을 세는지, 분모, 데이터 없음의 뜻). 증빙 미비는 "n건 / 집행 m건"으로 분모를 같이 보여 준다.
  - **상단 집행 합계 옆에 "미분류 n원 빠짐".** 미분류 집행은 어느 항목 잔액에도 들어가지 않아서 에듀파인 합계와 달라 보인다. 숨기지 않고 바로 옆에서 말한다.
  - **자동 백업 폴더는 백업 밖 별도 DB(`yesanjigi-device`)에 둔다.** 폴더 핸들은 기기 설정이지 데이터가 아니다. 권한이 풀리면 브라우저가 클릭 없이 묻지 못하므로 배너의 버튼으로 다시 허락받는다. 자동 백업 이름 꼴만 최신 14개를 남기고 사람이 만든 파일은 건드리지 않는다. 폴더 선택 대화상자는 헤드리스로 누를 수 없어 스모크에는 없다 — 보존 규칙만 단위 테스트.
- 2026-11-07 M5 (#18·#19) 계획 변경·추경.
  - **상태 표를 한 곳(`domain/revision.ts`)에 두고 모든 상태 × 모든 행동을 테스트로 훑는다.** 표에 없는 전이는 전부 거부된다.
  - **막다른 곳이 없게.** 반려·취소는 "복사해서 다시 작성"(전 금액을 지금 값으로 다시 찍는다), 확정은 반대 방향 변경안, 검토 중은 "작성 중으로 되돌리기".
  - **'전' 금액을 작성할 때 찍고, 확정할 때 그대로인지 다시 본다.** 두 변경안이 같은 배정을 바꾸면 늦게 확정하는 쪽이 낡은 숫자를 덮어쓴다 — 막고 다시 저장하게 한다.
  - **확정 = 변경안 상태 + 금액 반영을 한 transact로.** 반쯤 확정된 상태가 없다.
  - **계획 변경은 총액을 못 바꾸고, 추경은 총액이 바뀌어야 한다.** 두 종류가 섞이면 "n차 추경" 번호가 무의미해진다. 번호는 확정 순서로 매긴다.
  - **감액으로 잔액이 음수가 되는 항목은 무엇이 얼마나 모자라는지 말하며 막는다.**
  - **시점 조회는 저장하지 않고 되감는다.** 운영 중 금액은 변경안으로만 바뀌므로, 지금 값에서 그 뒤 확정된 변경안의 '전' 값을 거꾸로 덮으면 "n차 확정 직전"이 나온다. 1·2·3차 시나리오를 손 계산과 맞췄다.
  - **승인은 기록이지 통제가 아니다.** 혼자 쓰는 단계라 승인자 이름·일자·근거를 남길 뿐이다(PRD 비목표). 진짜 권한은 M7.
  - 스모크가 잡은 것: 저장할 때마다 편집기를 다시 그려 "제출했어요" 안내가 사라졌다. 편집기를 변경안 id로만 다시 그린다.
